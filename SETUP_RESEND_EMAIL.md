# Setting up welcome emails (Resend)

New player and staff accounts (created via onboarding CSV import, the
Players screen, the onboarding staff-invite step, or the staff API) now get
an emailed welcome message with their login details, sent through
[Resend](https://resend.com).

**Without this configured, account creation still works exactly as before**
— the app falls back to returning the temp password in the UI so the
manager can hand it over manually. Email is additive, not a hard dependency.

## 1. Create a Resend account + API key

1. Sign up at https://resend.com (free tier: 3,000 emails/month, 100/day).
2. Go to **API Keys** → **Create API Key**. Copy it — you only see it once.

## 2. (Recommended) Verify your club's sending domain

By default the app sends from `onboarding@resend.dev`, Resend's shared
sandbox sender — this works immediately with zero setup, but Resend will
only actually deliver sandbox-sender emails to **your own account's
verified email**, not to real players/staff. For real use:

1. In Resend, go to **Domains** → **Add Domain** (e.g. `yourclub.app`).
2. Add the DNS records Resend gives you (SPF/DKIM) at your domain registrar.
3. Once verified, set `RESEND_FROM_EMAIL` (see below) to something like
   `TeamMaster <noreply@yourclub.app>`.

## 3. Set environment variables

Add to `.env.local` (and to your Vercel project's Environment Variables):

```
RESEND_API_KEY=re_xxxxxxxxxxxxxxxxxxxxxxxx
RESEND_FROM_EMAIL=TeamMaster <noreply@yourclub.app>   # optional — see step 2
```

`NEXT_PUBLIC_APP_URL` should already be set to your deployed URL (e.g.
`https://teammaster.vercel.app`) — the welcome email's "Sign in" button
links there.

## 4. That's it

No redeploy-specific steps beyond setting the env vars — the email helper
(`lib/email.ts`) picks up `RESEND_API_KEY` at request time. Test it by
adding a player from the Players screen or running through onboarding.

## What happens if email fails or isn't configured

- Account creation **always succeeds** regardless of email delivery.
- The API response includes `emailSent: boolean` and, if `emailSent` is
  false, `emailError` with the reason.
- The Players screen surfaces this: if the email didn't send, the alert
  shows the temp password directly so you can share it manually.
- Placeholder addresses generated by the onboarding CSV importer
  (`@roster.local`, used when a player row has no email) are skipped
  entirely — there's no real inbox behind those.
